## پروژه

### در یک جمله

**Français avec Dino یک پلتفرم وب است که یادگیری زبان فرانسه را به شکل مسیرهای تدریجی سازمان‌دهی می‌کند، نه صرفاً مجموعه‌ای از صفحات و درس‌های مستقل.**

کاربر می‌تواند روی دستور زبان، واژگان، تمرین‌ها و موقعیت‌های واقعی مانند فرودگاه، هتل، رستوران یا شرایط اضطراری کار کند.

این پروژه به‌طور ویژه برای **فارسی‌زبانانی که فرانسه یاد می‌گیرند** مناسب است. زبان اصلی یادگیری همچنان فرانسه است، اما رابط کاربری و بخش زیادی از کمک‌های آموزشی می‌توانند به فارسی نمایش داده شوند.

### تجربه کلی کاربر

```text
انتخاب زبان رابط
        ↓
انتخاب مسیر یادگیری
        ↓
تعیین یا انتخاب سطح
        ↓
انتخاب موضوع یا درس
        ↓
مطالعه محتوا
        ↓
انجام تمرین
        ↓
ذخیره پیشرفت
```

محتوا از سطح‌های **CEFR / CECRL** استفاده می‌کند:

```text
A1 → A2 → B1 → B2 → C1 → C2
```

> پوشش همه بخش‌ها یکسان نیست. برای مثال داده‌های واژگان تا C2 وجود دارند، در حالی که بعضی مسیرهای دیگر فعلاً بیشتر روی سطح‌های پایین‌تر متمرکز هستند.

## MVP فعلی

هدف MVP فعلی این نیست که تمام قابلیت‌های یک پلتفرم آموزشی کامل را داشته باشد. هدف اصلی داشتن یک **هسته آموزشی قابل استفاده، قابل توسعه و قابل تست** است.

| بخش | وضعیت فعلی |
|---|---|
| Onboarding | ✅ موجود |
| آزمون تعیین سطح | ✅ موجود |
| دستور زبان | ✅ قابل استفاده |
| واژگان | ✅ قابل استفاده |
| مسیر سفر | ✅ قابل استفاده |
| تمرین و Quiz داخل محتوا | ✅ بسته به محتوا |
| جستجو | ✅ موجود |
| اخبار | ✅ موجود |
| نظرسنجی | ✅ قابلیت موجود |
| Daily، Games، صفحه عمومی Exercises و Profile | خارج از محدوده منتشرشده؛ هیچ مسیر نمایشی ناقصی ارائه نمی‌شود |
| حساب کاربری آنلاین | ❌ پیاده‌سازی نشده |
| همگام‌سازی بین دستگاه‌ها | ❌ پیاده‌سازی نشده |

پیشرفت کاربر در حال حاضر عمدتاً با `localStorage` ذخیره می‌شود.

در نتیجه:

- پیشرفت بین مرورگرها و دستگاه‌ها همگام نمی‌شود؛
- پاک کردن داده‌های محلی سایت می‌تواند پیشرفت ذخیره‌شده را حذف کند.

## قابلیت‌ها

### 📚 دستور زبان

بخش Grammar یک انتخابگر سطح از **A1 تا C1** و درس‌های سازمان‌دهی‌شده بر اساس سطح ارائه می‌کند.

یک درس می‌تواند شامل این موارد باشد:

- توضیح؛
- مثال؛
- جدول؛
- نکات آموزشی؛
- تمرین یا Quiz؛
- ثبت پیشرفت هر بخش؛
- Bookmark.

منطق بارگذاری و پیشرفت از HTML جدا شده است.

### 🧠 واژگان

بخش Vocabulary مقدار زیادی محتوای دسته‌بندی‌شده بر اساس سطح و موضوع دارد.

فعالیت‌ها شامل مواردی مانند:

- Flashcards؛
- داستان ساده؛
- داستان پیشرفته‌تر؛
- Quiz؛
- بازی‌های ساخته‌شده از واژه‌های هر بسته: حدس کلمه، جستجوی کلمات و جدول کلمات متقاطع؛
- ثبت کلمات دشوار؛
- مرور اختصاصی کلمات ضعیف.

داده‌های واژگان در چند سطح تا **C2** وجود دارند، اما مقدار محتوا در همه موضوع‌ها یکسان نیست.

### ✈️ سفر

مسیر Travel بر موقعیت‌های واقعی تمرکز دارد، نه فقط قواعد جداگانه.

موضوعات شامل مواردی مانند:

- الفبا و اعداد کاربردی؛
- مکالمه‌های کوتاه؛
- فرودگاه و کنترل مرزی؛
- چمدان؛
- حمل‌ونقل از فرودگاه؛
- هتل و پذیرش؛
- بانک و تبدیل ارز؛
- تلفن و اینترنت؛
- آب‌وهوا؛
- رستوران و کافه؛
- پرسیدن مسیر؛
- خرید؛
- گردشگری؛
- امنیت؛
- سلامت و شرایط اضطراری؛
- خروج و خداحافظی.

داده‌های Travel می‌توانند ترکیبی از این موارد باشند:

```text
فرانسه
+
فارسی
+
راهنمای تلفظ
+
زمینه کاربرد
+
تمرین
```

### 🔎 جستجو، اخبار و نظرسنجی

مخزن همچنین قابلیت‌های Search، News و Polls را دارد. این بخش‌ها مکمل هسته آموزشی هستند، اما فعلاً مسیرهای اصلی MVP محسوب نمی‌شوند.

## چندزبانه‌سازی (i18n)

Dino اکنون یک لایه اختصاصی برای Internationalization دارد.

```text
src/i18n/
├── fr.ts
├── fa.ts
└── i18n.ts
```

### زبان‌های رابط

در حال حاضر دو زبان رابط پشتیبانی می‌شوند:

```text
fr → français
fa → فارسی
```

زبان انتخاب‌شده در این مقدار ذخیره می‌شود:

```text
localStorage["language"]
```

Runtime همچنین این موارد را هماهنگ می‌کند:

- `document.documentElement.lang`
- `document.documentElement.dir`
- عنوان صفحه

فرانسه `ltr` است و فارسی `rtl`.

### `fr.ts` : کاتالوگ مرجع

کاتالوگ فرانسوی کلیدهای اصلی رابط را تعریف می‌کند.

به‌صورت مفهومی:

```ts
const frMessages = {
    "common.back": "Retour",
    "common.continue": "Continuer",
    "navbar.grammar": "Grammaire"
} as const;

type TranslationKey = keyof typeof frMessages;
```

بنابراین `TranslationKey` مستقیماً از کاتالوگ مرجع ساخته می‌شود.

### `fa.ts` : همان قرارداد برای فارسی

کاتالوگ فارسی باید دقیقاً همان کلیدها را پیاده‌سازی کند:

```ts
const faMessages: Record<TranslationKey, string> = {
    "common.back": "بازگشت",
    "common.continue": "ادامه",
    "navbar.grammar": "دستور زبان"
};
```

اگر کلیدی فراموش شود یا اشتباه باشد، TypeScript می‌تواند آن را تشخیص دهد.

### `i18n.ts` : Runtime

Runtime توابع اصلی زیر را فراهم می‌کند:

```text
t(...)
getI18nLanguage()
setI18nLanguage(...)
applyDocumentLanguage(...)
localizedValue(...)
localizedTextClass()
```

برای متن رابط:

```ts
t("common.back")
```

برای محتوای آموزشی دو‌زبانه‌ای که از قبل در JSON ذخیره شده است:

```ts
localizedValue(
    item.title,
    item.title_fa
)
```

### متن رابط و محتوای آموزشی جدا هستند

قانون اصلی:

```text
src/i18n/*.ts
    =
متن رابط برنامه

data/**/*.json
    =
محتوای آموزشی
```

بنابراین درس‌ها نباید داخل کاتالوگ i18n کپی شوند.

### شرط زبان نباید وارد منطق برنامه شود

Controller و Engine نباید دوباره چنین الگویی داشته باشند:

```ts
if (lang === "fa") {
    ...
}
```

متن رابط باید از `t()` عبور کند و محتوای آموزشی دو‌زبانه باید از `localizedValue()` استفاده کند.

این قانون با تست‌های معماری محافظت می‌شود.

### مسئولیت‌ها

MVP به سمت این جداسازی حرکت کرده است:

```text
app.ts / router.ts
    → راه‌اندازی و Navigation اصلی

pages/ + feature controllers
    → هماهنگ‌سازی، Eventها و State صفحه

core/*Engine.ts + feature engines
    → منطق و State قابل استفاده مجدد

ui/views/*.ts
    → HTML و Presentation

    → متن رابط و LTR/RTL

data/**/*.json
    → محتوای آموزشی

types/
    → قراردادهای TypeScript
```

### Navigation قابل اشتراک‌گذاری

هر صفحه پایدار یک Query String استاندارد دارد؛ برای نمونه:

```text
?view=grammar&level=A1
?view=grammar&lesson=A1-G-001
?view=vocabulary&level=B1&pack=arrival-office
?view=travel&lesson=TR-006
?view=journal&article=2026-w34-azadi-tower
?view=info&page=about
```

این URLها بازشدن مستقیم، Reload و دکمه‌های Back/Forward مرورگر را پشتیبانی می‌کنند. Router تنها مالک `location` و `history` است، شناسه‌ها را پیش از نمایش اعتبارسنجی می‌کند و Deep Link را در تمام مراحل Onboarding نگه می‌دارد. Stateهای موقت—سؤال جاری، امتیاز، کارت برگردانده‌شده، صفحه بازی یا زیربخش—عمداً وارد URL نمی‌شوند.

### Controller / Page

Controller می‌تواند:

- رویداد کاربر را دریافت کند؛
- Engine را صدا بزند؛
- State موقت صفحه را مدیریت کند؛
- View را صدا بزند؛
- در صورت نیاز DOM از قبل ساخته‌شده را مدیریت کند.

اما نباید دوباره Templateهای بزرگ HTML را در خود نگه دارد.

### Engine

Engine مسئول منطق قابل استفاده مجدد است:

- بارگذاری داده؛
- محاسبه؛
- انتخاب سؤال؛
- اعتبارسنجی جواب؛
- Progress؛
- Placement؛
- State منطقی.

Engine نباید Template رابط بسازد.

### View

فایل‌های `src/ui/views/` مسئول Presentation هستند:

- HTML ساختاری؛
- Labelها؛
- Layout هر صفحه؛
- Attributeهای `data-*` برای اتصال Eventها؛
- استفاده از i18n.

### `data/`

اصل مهم:

```text
src/  = برنامه چگونه کار می‌کند
data/ = برنامه چه چیزی آموزش می‌دهد
```

درس‌ها و Packها عمدتاً در JSON نگهداری می‌شوند تا محتوای آموزشی بتواند مستقل از Engine رشد کند.

### ES modules و Dependencyهای صریح

Dino فعلاً از React یا Vue استفاده نمی‌کند.

TypeScript برنامه به‌صورت **ES modules** کامپایل می‌شود. `index.html` فقط یک entry point به نام `app.js` را با `type="module"` بارگذاری می‌کند. هر Dependency اجرایی یا نوعی با `import` و APIهای مشترک با `export` صریح تعریف می‌شوند.

مرورگر اکنون ترتیب بارگذاری را از روی گراف Moduleها تعیین می‌کند و این ترتیب دیگر به‌صورت دستی در HTML نگهداری نمی‌شود.

### گراف Dependency

[گراف تولیدشده برنامه](docs/dependency-graph.md) همه Dependencyهای محلی قابل دسترس از `app.ts` را نشان می‌دهد. ابتدا نمای کلی لایه‌ها و سپس نقشه‌های بازشونده هر دامنه را ارائه می‌کند. Importهای type-only ردیابی می‌شوند، اما برای خوانایی در نمودارها نمایش داده نمی‌شوند.

```bash
npm run graph:dependencies
npm run graph:dependencies:check
```

خروجی قطعی است: فرمان اول گراف را دوباره تولید می‌کند و فرمان دوم بدون نوشتن فایل، به‌روز بودن آن را بررسی می‌کند.
Generator هر چرخه Dependency اجرایی را رد می‌کند. تست‌های معماری نیز Dependencyهای View → Feature/Page، Feature → Page و Engine → UI/Controller را ممنوع می‌کنند.

## تست‌ها و کیفیت

### دستورات

```bash
npm test
npm run test:app
npm run test:data
npm run test:architecture
npm run test:e2e:install
npm run test:e2e
npm run typecheck
npm run build
npm run knip
npm run duplication
npm run graph:dependencies:check
```

`npm test` به‌صورت خودکار تمام فایل‌های مطابق این الگو را اجرا می‌کند:

```text
tests/**/*.test.ts
```

بنابراین با اضافه کردن تست جدید لازم نیست `package.json` تغییر کند.
فرمان `npm run test:app` زیرمجموعه مسدودکننده خط کیفیت کد است؛ تست‌های داده عمداً در `npm run test:data` و Workflow اختصاصی خود جدا می‌مانند.

### تست E2E مرورگر

مجموعه Playwright راه‌اندازی واقعی برنامه، تغییر رابط فرانسوی ↔ فارسی (متن قابل مشاهده، `lang` و `dir`) و ماندگاری زبان پس از Navigation و Reload کامل را بررسی می‌کند.

پیش از نخستین اجرای محلی، فقط Chromium را نصب کنید:

```bash
npm run test:e2e:install
```

سپس سناریوها را روی Build تولیدی اجرا کنید؛ سرور به‌صورت خودکار روی یک Port محلی ثابت شروع می‌شود:

```bash
npm run test:e2e
```

نصب Chromium به دسترسی شبکه نیاز دارد. هیچ سرور دستی یا Screenshot مرجع لازم نیست.

### تست داده

تست‌های این مسیر:

```text
tests/data/
```

سازگاری داده‌های آموزشی را بررسی می‌کنند.

در حال حاضر مخزن شامل تست سازگاری شناسه‌های درس‌های Travel است.

### تست معماری

تست‌های این مسیر:

```text
tests/architecture/
```

برای جلوگیری از Regression ساختاری هستند.

`ui-boundaries.test.ts` از موارد زیر محافظت می‌کند:

- بازگشت HTML ساختاری به Controller، Page یا Engine؛
- بازگشت Handlerهای inline مانند `onclick="..."`؛
- بازگشت شرط مستقیم زبان به Business logic؛
- حذف Viewهای مهاجرت‌داده‌شده؛
- بازگشت renderer قدیمی Travel؛
- بازگشت classic scriptها یا چند entry point به `index.html`.

بنابراین معماری فقط یک Convention متنی نیست؛ یک Regression guard قابل اجرا دارد.

### CI

GitHub Actions در حال حاضر این سیاست را دارد:

```text
application tests → شکست آن Job را قرمز می‌کند
TypeScript        → شکست آن Job را قرمز می‌کند
production build  → شکست آن Job را قرمز می‌کند
Knip              → فقط گزارش
jscpd             → فقط گزارش
```

تنظیم Branch protection یا Ruleset در GitHub موضوعی جدا از کد مخزن است.

Workflow اختصاصی **Dependency graph** فرمان `npm run graph:dependencies` را اجرا و نتیجه را با `docs/dependency-graph.md` مقایسه می‌کند. تغییر Import بدون تولید دوباره گراف، این Job را ناموفق می‌کند.
Workflow اختصاصی **Corpus quality** فرمان `npm run test:data` را اجرا می‌کند، خطاهای خوانا را به تفکیک فایل و فیلد منتشر می‌کند و یک گزارش ماندگار را در Pull Request به‌روز نگه می‌دارد.
Workflow اختصاصی **Browser E2E** فقط Chromium را نصب می‌کند، Build محلی را اجرا می‌کند و در صورت Regression راه‌اندازی یا i18n، CI را ناموفق می‌کند.

- npm

node --version

git --version

```bash

```

مثال:

```bash
python -m http.server 8080 --directory dist
```

سپس:

```text
http://localhost:8080
```

## اضافه کردن محتوای آموزشی

محتوای آموزشی باید تا حد ممکن مستقل از کد برنامه باقی بماند.

مثال:

```text
data/lessons/       → درس‌های عمومی / Grammar
data/vocabulary/    → Packهای واژگان
data/travel/        → مسیر Travel
```

برای Travel:

```text
data/travel/lessons.json
```

Index را نگه می‌دارد و فایل‌های درس در این مسیر هستند:

```text
data/travel/lessons/
```

قبل از اضافه کردن محتوا بررسی کنید:

1. شناسه پایدار و یکتا باشد؛
2. ساختار با Contract مورد انتظار مطابقت داشته باشد؛
3. Index و فایل‌های جزئی با هم سازگار باشند؛
4. ترجمه آموزشی مورد نیاز وجود داشته باشد؛
5. `npm test` موفق باشد.

## مشارکت

### قبل از Pull Request

حداقل:

```bash
npm test
npm run typecheck
npm run build
```

در صورت نیاز:

```bash
npm run knip
npm run duplication
```

### اصول

- تغییرات را محدود و هدفمند نگه دارید؛
- اگر Engine مشترک وجود دارد، Engine جدید و تکراری نسازید؛
- HTML ساختاری را در `src/ui/views/` نگه دارید؛
- برای متن رابط از `t()` استفاده کنید؛
- برای داده آموزشی دو‌زبانه از `localizedValue()` استفاده کنید؛
- محتوای آموزشی را تا حد ممکن در `data/` نگه دارید؛
- از فایل‌های بسیار بزرگ و چندمسئولیتی اجتناب کنید؛
- شناسه‌های پایدار را حفظ کنید؛
- برای Invariantهای مهم تست اضافه کنید.

### جهت معماری

هدف این است که پروژه به این ساختار نزدیک‌تر شود:

```text
Controllerهای ساده
        +
Engineهای قابل استفاده مجدد
        +
Viewهای اختصاصی
        +
محتوای JSON
        +
i18n متمرکز
        +
Dependencyهای صریح
```

Importهای صریح اکنون گراف معماری را به‌صورت خودکار تغذیه می‌کنند و Dependencyهای نامطلوب را در Code review قابل مشاهده می‌سازند.

## جهت محصول

گام‌های طبیعی بعدی شامل مواردی مانند:

- تکمیل مسیر Daily؛
- توسعه Games؛
- تکمیل صفحه عمومی Exercises؛
- ساخت Profile؛
- قوی‌تر کردن تمرین‌ها؛
- اضافه کردن تست‌های بیشتر برای داده‌ها؛
- استفاده از اشتباهات زبان‌آموز برای پیشنهاد مرور؛
- هماهنگ‌تر کردن پوشش سطح‌های CEFR؛
- در آینده، احتمالاً اضافه کردن حساب کاربری و Sync بین دستگاه‌ها.

این موارد **جهت آینده** هستند و به معنی پیاده‌سازی فعلی آن‌ها نیستند.
